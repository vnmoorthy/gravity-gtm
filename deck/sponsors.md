# Gravity: sponsor integrations one-pager

**Live demo:** https://gravity-gtm.onrender.com · **Code:** https://github.com/vnmoorthy/gravity-gtm

Gravity is a self-driving GTM engine: one sentence in, booked meetings out. Every claim is cited, every send is approved, and every credit is metered. Each sponsor below sits in the critical path, not on a logo wall. Code lives in `server/*.js`.

Top-up resumes it. | `{FLEXPRICE_BASE_URL=https://us.api.flexprice.io/v1}`: `POST /events` (`event_name`, `external_customer_id`, `event_id`, `timestamp`, `source`, `properties`), `POST /customers`, `GET /customers/wallets?id=…`, `POST /wallets`, `POST /wallets/{id}/top-up`. The Usage event stream Sync column reads `flexprice`, and the same events appear in the Flexprice dashboard. |

### Moss (moss.dev): semantic search runtime
| How it's used | API | Env | Demo moment |
|---|---|---|---|
| Gravity indexes every account, buyer, signal and competitor into a Moss index and uses hybrid (semantic + keyword) retrieval for the **⌘K Ask Gravity** bar, **lookalike accounts**, **Reviewer evidence retrieval** (each draft is matched to its most relevant cited signals) and **Writer grounding** (persona pains are matched to signals before drafting). Every search and lookalike call is metered as `semantic_query` (0.5 credits) in Flexprice. Without keys, a local hybrid engine (BM25 + trigram cosine) is the fallback. | `@moss-js/moss` (`MossClient`, `createIndex`, `loadIndex`, `query`); app routes `GET /api/search?q=`, `GET /api/accounts/:id/lookalikes`, `POST /api/moss/sync` (`server/moss.js`) | `MOSS_PROJECT_ID`, `MOSS_PROJECT_KEY`, `MOSS_INDEX` (default `gravity-workspace`), `MOSS_MODEL` (default `moss-minilm`) | Press ⌘K and type "CFOs hiring after a Series C". Ranked results appear with the engine badge and timing. Then open an account and find lookalikes. In HITL Review, point at the Moss evidence on a draft. |

**Supporting, all real calls**
- **DNS (Node `dns/promises`):** `resolve4` and `resolveMx` per domain, with the MX provider detected (Google Workspace, Microsoft 365, Proofpoint, Mimecast). This drives email confidence. `.example` domains return illustrative MX for demo data only.
- **Hunter.io:** `GET https://api.hunter.io/v2/email-finder` (`HUNTER_API_KEY`). Only used when keyed. Otherwise Gravity falls back to pattern synthesis plus MX.
- **Resend / SendGrid:** `POST https://api.resend.com/emails` or `https://api.sendgrid.com/v3/mail/send` after HITL approval. `DISPATCH_MODE=sandbox` (the default) redirects every send to `TEST_INBOX`. With no key, the send is simulated and labelled.
- **CI smoke test:** `.github/workflows/ci.yml` boots the server and runs `scripts/smoke.js` end to end (intake → ICP → discovery → graph queries → red-team lie caught → approvals → credit gate 402 → top-up → Nexla push).

**Honest scope notes:** Every integration (Teamily MCP, RocketRide, HotData, Flexprice, Moss, Claude, Band, Nexla, Hunter, Neo4j, email) switches on only when their keys are set. Without them the app runs in a labelled demo mode. Buyer Twin replies on the Pipeline are simulations and are labelled so in the toast and the audit log. Real replies arrive through `POST /api/webhooks/reply`. LinkedIn touches are copy-to-send, because the LinkedIn API needs partner access.

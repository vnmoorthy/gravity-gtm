# Gravity: sponsor integrations one-pager

**Live demo:** https://gravity-gtm.onrender.com · **Code:** https://github.com/vnmoorthy/gravity-gtm

Gravity is a self-driving GTM engine: one sentence in, booked meetings out. Every claim is cited, every send is approved, and every credit is metered. Each sponsor below sits in the critical path, not on a logo wall. Code lives in `server/*.js`. The sidebar status list in the app (Claude, Flexprice, Band, Neo4j, Hunter, Email, Nexla, Snyk CI) shows which integrations are live.

**Supporting, all real calls**
- **DNS (Node `dns/promises`):** `resolve4` and `resolveMx` per domain, with the MX provider detected (Google Workspace, Microsoft 365, Proofpoint, Mimecast). This drives email confidence. `.example` domains return illustrative MX for demo data only.
- **Hunter.io:** `GET https://api.hunter.io/v2/email-finder` (`HUNTER_API_KEY`). Only used when keyed. Otherwise Gravity falls back to pattern synthesis plus MX.
- **Resend / SendGrid:** `POST https://api.resend.com/emails` or `https://api.sendgrid.com/v3/mail/send` after HITL approval. `DISPATCH_MODE=sandbox` (the default) redirects every send to `TEST_INBOX`. With no key, the send is simulated and labelled.
- **CI smoke test:** `.github/workflows/ci.yml` boots the server and runs `scripts/smoke.js` end to end (intake → ICP → discovery → graph queries → red-team lie caught → approvals → credit gate 402 → top-up → Nexla push).

**Honest scope notes:** Claude, Band, Flexprice, Nexla, Hunter, Neo4j and email each switch on only when their keys are set. Without them the app runs in a labelled demo mode. Buyer Twin replies on the Pipeline are simulations and are labelled so in the toast and the audit log. Real replies arrive through `POST /api/webhooks/reply`. LinkedIn touches are copy-to-send, because the LinkedIn API needs partner access.

## Moss (moss.dev): semantic search runtime
- **How it's used:** Gravity indexes every account, buyer, signal and competitor into a Moss index (`@moss-js/moss`: `createIndex`, `addDocs` with upsert, `loadIndex`, `query` with hybrid `alpha`). Moss serves the **⌘K Ask Gravity** bar, **Find lookalikes** on Accounts, **Reviewer evidence retrieval** (each draft is matched to its most relevant cited signals), and **Writer grounding** (persona pains are matched to signals before drafting). Every query is metered as `semantic_query` in Flexprice.
- **Env:** `MOSS_PROJECT_ID`, `MOSS_PROJECT_KEY` (optional `MOSS_INDEX`, `MOSS_MODEL=moss-minilm`). Without keys, a local hybrid engine (BM25 + trigram cosine) keeps every feature working, and the UI badge reads "Moss · local fallback".
- **Demo moment:** press ⌘K and type "CFOs hiring after a Series C". Ranked results appear in a few ms with the engine badge. Then open an account, click **Find lookalikes**, and in HITL Review point at "Evidence retrieved · Moss".
